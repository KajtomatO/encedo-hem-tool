with the same guarantees it had in the SDK, plus the two gates the split
calls for: `public_api_only` (REQ-PKG-002 — the tool sources include only
`ehem/*.h`, their own headers and the vendored QR encoder) and
`conformance_sync` (REQ-TOOL-030 — the literals the C tests assert against
match `conformance/*.json`).

`crypto_ref_*` modules are in the submodule, outside the scanned tree) and
now demands zero backend includes under `c/tests/`. The package-mode CI
leg (STEP-T1-050) is the second half of REQ-PKG-002: there `sdk/src` is
not on any include path by construction. `conformance_sync` reads the JSON
with a small C or CMake checker — no JSON library in the tests: the
expected strings are compared as text.
